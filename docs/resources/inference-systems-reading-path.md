# 大模型推理系统论文阅读路径

读推理系统论文时，可以沿着一次请求的生命周期追问四件事：请求如何进入并组成批次，哪些状态需要跨阶段或跨请求保留，执行如何适应不同硬件，以及论文怎样证明端到端收益。下面的论文按问题递进排列，不代表后一个系统全面优于前一个。

## 1. 请求怎样被组织

从 **Orca**（OSDI 2022）看 iteration-level scheduling：服务为何需要在每轮生成后重新组织 batch？再读 **vLLM / PagedAttention**（SOSP 2023）：动态批处理会增加 KV cache 管理压力，分页式管理解决的是哪类碎片与共享问题？阅读时区分请求等待时间、首 token 延迟、生成吞吐和显存利用率，避免用单一指标概括服务质量。

## 2. 状态怎样跨阶段复用

**DistServe**（OSDI 2024）把 prefill 与 decode 分开部署。除了各自扩容的收益，还要关注 KV 状态传递和跨阶段协调的代价。**RAGCache**（2024）把检索注入后的中间状态纳入缓存讨论；它提醒我们，缓存检索结果和复用模型计算并不是同一件事。读这两篇时，可以画出状态的产生、传输、驻留、失效与再次使用路径。

## 3. 有限或异构硬件怎样执行

**FlexGen**（2023）讨论 GPU、CPU 和磁盘之间的数据放置、访问顺序与压缩如何协同；**PowerInfer**（SOSP 2024）则从激活分布出发组织 GPU/CPU 异构执行。两者的优化对象不同，不能把论文中的硬件或负载收益直接套到另一种模型和设备上。复现实验时，应同时报告模型、硬件、输入与输出长度、并发、传输开销及基线配置。

## 4. 用同一套问题审视新系统

1. **生命周期**：请求如何排队、合批、进入 prefill/decode，并通过流式接口返回？
2. **状态**：KV、外部知识和跨轮记忆各由谁维护，何时可复用，何时必须失效？
3. **控制**：队列、缓存命中、设备容量等反馈如何影响调度和放置？
4. **证据**：收益是局部算子、单请求，还是端到端服务收益？对照组是否保持相同输出、负载与正确性约束？
