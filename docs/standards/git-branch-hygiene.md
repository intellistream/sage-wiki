# Git 分支盘点与安全收尾

本页整理通用仓库维护经验，不包含内部项目分支、人员信息或未公开实验记录。目标是确认真实远程状态和成果归属，再决定是否收尾。

## 先确认看到的是什么

`git branch -r` 显示本地保存的远程跟踪引用，不等于服务器上全部分支。克隆配置可能只获取某一分支。先执行只读检查：

```bash
git status --short
git remote -v
git config --get-all remote.origin.fetch
git ls-remote --heads origin
```

不要把含令牌的远程地址粘贴到日志或公开讨论。发现列表不一致时，先检查 fetch refspec；不要据此认定其他分支不存在。需要扩大抓取范围时，应确认仓库规模、权限与当前工作，再更新 refspec 并抓取。`fetch --prune` 会清理已消失远程引用的本地跟踪记录，不会代替成果归档。

## 判断分支是否还有独立成果

确定目标主分支和待审查分支后，比较提交差异、文件差异和关联评审。下列命令中的分支名是占位符，须替换为已核对的引用：

```bash
git log origin/main..origin/topic
git rev-list --left-right --count origin/main...origin/topic
git diff origin/main...origin/topic
```

没有未合并提交不一定表示可以删除：实验输出、未跟踪文件、运行任务或其他工作区仍可能依赖该分支。反过来，压缩合并后的提交哈希不同，也不一定代表成果未入主线。应检查最终内容和测试证据。

## 收尾验收

- 明确合并目标，检查提交范围，保留他人未提交修改。
- 验证目标主线包含所需内容及测试，不以 PR 关闭状态替代验证。
- 删除前确认所有者、运行依赖及可恢复引用；有疑问先归档，不强删。
- 合并与分支删除是不同操作；只在已获授权的范围内执行。
- 最后报告主线提交、验证结果及保留的恢复点，不留下无人解释的临时分支。
