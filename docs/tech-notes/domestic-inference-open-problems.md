## 目的

本文梳理了国产算力平台大模型推理引擎领域当前可通过实验验证的开放研究问题。每个问题映射到相关技术方向，给出待验证假设和所需实验基础设施。

适用于：推理引擎方向的课题探索、benchmark 设计、论文选题。

## 三层系统视角

这些问题可按三条相互关联的技术线组织：资源编排层研究异构设备调度、混部干扰和服务目标；记忆与检索中间件层研究状态生命周期、索引和数据流；执行层研究推理引擎、算子与硬件适配。跨层问题需要分别测量资源等待、检索与状态操作、模型执行开销，不能仅靠一个端到端数字判断瓶颈。本框架是选题组织方式，不代表已经实现的系统能力或性能承诺。

---

## 1. 后端执行路径分叉代价量化

**核心判断：** 共享路径分叉导致正确性边界不一致、维护成本持续上升。但目前缺乏量化证据说明分叉到底带来了多少实际性能损失和维护负担。

### 实验问题

- **Q1.1:** 国产后端 vs 上游主流框架在同一模型（如 Qwen2.5-7B）上的 feature parity 差距有多大？列出当前不支持或性能不达标的功能清单（graph mode、speculative decoding、prefix caching、PD 分离等）。
- **Q1.2:** 插件化适配方式相比侵入式修改，在性能上付出了多少代价？对比同一功能的侵入式实现 vs 插件实现的吞吐差异。
- **Q1.3:** 上游每次大版本升级，下游适配需要多少工程量？统计历史上的 merge conflict 数量和解决时间。

---

## 2. 复杂任务场景的状态治理压力

**核心判断：** 多模态、结构化输出、工具调用等复杂请求进入运行时后，会同时冲击调度、缓存和图模式。关键问题不在接口名义上"可用"，而在端到端时延和稳定性。

### 实验问题

- **Q2.1:** 混合文本+多模态请求时，视觉 token 膨胀对共存的纯文本请求 p99 时延有多大干扰？量化资源争用效应。
- **Q2.2:** 结构化输出（grammar-constrained decoding）的额外开销有多大？对比开启/关闭约束时的吞吐差异。
- **Q2.3:** 工具调用场景下的暂停-恢复机制是否引入了不可忽略的 KV cache 管理开销？

---

## 3. Prefix Caching 与 KV 状态治理

**核心判断：** 前缀索引、多级驻留和状态迁移能力一旦不足，问题通常先在长上下文和高并发条件下显现。

### 实验问题

- **Q3.1:** prefix caching 的实际命中率在不同工作负载分布下（对话、文档问答、代码补全）分别是多少？
- **Q3.2:** 长上下文场景（32K-128K tokens）下，KV cache 的分页管理是否引入了额外的碎片化开销？
- **Q3.3:** PD 分离（prefill-decode disaggregation）场景下，KV 传输延迟占端到端 TTFT 的比例是多少？

---

## 4. 压缩收益的稳定性验证

**核心判断：** 同一组量化参数在不同后端、不同上下文长度和不同负载强度下，可能分别表现为吞吐提升、尾时延恶化、状态迁移变多或精度明显波动。

### 实验问题

- **Q4.1:** W4A16/W8A8 量化的加速比在不同 batch size 和 sequence length 下是否稳定？是否存在"量化反而变慢"的工作点？
- **Q4.2:** 量化后的 KV cache 压缩能否稳定减少内存占用同时不恶化 TPOT？
- **Q4.3:** 在实际 serving 场景下，低比特推理的单位 token 成本相比 FP16 到底优化了多少？

---

## 5. 评测体系：从展示型到决策型

**待验证假设：** 只使用固定 batch、固定上下文长度的评测，可能遗漏突发、缓存失效和负载漂移下的服务行为；应比较不同评测协议能否改变系统排序。

### 实验问题

- **Q5.1:** 设计多阶段 disturbance benchmark（稳态→突发→缓存失效→负载漂移→恢复），对比单点 benchmark 结论是否一致。
- **Q5.2:** 多租户混部场景下，系统的吞吐稳定性（jitter）与 SLO 达成率是多少？
- **Q5.3:** 版本升级对性能的影响：每次大版本更新后，同一 workload 的性能回归幅度是多少？

---

## 6. 插件化架构的长期可持续性

**核心判断：** 插件化适配方式的核心价值在于 merge-safe，但其长期可持续性需要数据支撑。

### 实验问题

- **Q6.1:** 代码变更中，有多少比例落在可独立演进的外围接口，多少比例不得不修改上游共享模块？
- **Q6.2:** 新模型接入的适配周期是多少天？与侵入式修改路线的跟进速度对比。
- **Q6.3:** 上游更新导致的后端 break 频率和修复耗时如何？

## 优先级映射

| 问题 | 难度 | 数据价值 | 建议执行顺序 |
|------|------|---------|------------|
| Q5 (评测体系) | 低 | 极高 | 1 — 定义方法论 |
| Q6 (插件化可持续性) | 低 | 高 | 2 — 只需分析历史数据 |
| Q1 (后端分叉代价) | 中 | 高 | 3 |
| Q3 (KV 状态治理) | 中 | 高 | 4 |
| Q4 (压缩稳定性) | 中 | 高 | 5 |
| Q2 (复杂任务状态) | 高 | 高 | 6 |

Q5（评测体系）是最高杠杆的第一步，因为它定义了所有后续实验应遵循的评测方法论。

---

## 如何使用这些研究问题

每个实验结果应以如下方式集成：
1. 作为挑战分析的实证段落，将"判断"升级为"判断+证据"
2. 作为引擎比较的量化补充，使路线比较从定性走向定量
3. 作为未来方向的落地验证

目标不是变成 systems paper，而是用可复现的实验数据增强论断的可信度。
