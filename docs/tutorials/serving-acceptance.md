# 推理服务部署与端到端验收

本页是一份通用验收流程，不公布内部服务器地址、账号、密钥或资源分配。实际启动命令应以目标引擎对应版本的官方文档和已审核配置为准。

## 一次请求经过哪些层

```text
客户端 → 认证与请求路由 → 推理引擎 → 加速器执行
                ↓
          请求记录与用量统计
```

若应用还需要检索，检索、重排与提示词构造通常发生在调用推理服务之前。模型服务健康不代表检索和应用工作流都正常。

| 层次 | 要验证的行为 | 常见误判 |
| --- | --- | --- |
| 客户端 | profile、模型、provider、协议与目标地址正确 | 启动成功就认为选中了指定模型 |
| 网关 | 身份校验、模型路由、错误透传、流结束正确 | HTTP 200 就认为回答完成 |
| 引擎 | 检查点、并行配置、上下文容量与运行参数正确 | 进程存在就认为能服务 |
| 应用 | 检索命中、工具调用、答案与引用均符合问题 | 只看最终回复是否流畅 |

## 部署前记录

记录模型的完整标识与修订、引擎提交、依赖版本、设备数量、并行方式、显存规划、最大输入输出范围。共享设备应先核对分配与现有进程。Ascend 环境另见[版本匹配指南](ascend-npu-setup.md)。

上下文容量需要包含系统提示词、历史消息、工具定义、检索材料和预留输出。模型宣称支持的窗口、引擎启动上限、网关限制与客户端预算必须分别确认。

## 最小验收矩阵

| 测试 | 输入设计 | 通过条件 |
| --- | --- | --- |
| 基础回答 | 要求回复一个固定短语 | 正确模型身份、正常结束、内容准确 |
| 流式回答 | 可控的短问题 | 持续收到有效事件，最后有协议规定的完成事件 |
| 工具调用 | 执行只读命令，如查看目录或仓库状态 | 有真实工具调用及工具输出，不能仅有模型声称执行 |
| 上下文边界 | 逐步增大可重复的输入 | 边界内可完成，超限时给出明确错误且无静默换模型 |
| 检索问答 | 使用有已知来源的事实问题 | 命中正确来源，答案忠实，链接可打开 |
| 并发与失败 | 小规模并发、无效模型名、取消请求 | 限流与错误可辨认，取消后资源能释放 |

测试数据只使用获授权的资料。测试 key 从安全环境读取，结果中不保存 key、完整认证头或私人提示词。

## 发生问题时如何定位

**入口不可达**：分别检查应用本地健康端点、反向代理或隧道、DNS 和公网访问。公网 502 与模型推理错误不是同一类故障。

**流开始但没有最终答案**：核对结束事件、finish reason、输出与思考 token 使用、超时位置。错误被网关包装成 200 时，客户端仍可能拿到不完整结果。

**工具测试退出码为 0，但没有执行**：核对工具事件与系统调用输出。容器 namespace 或只读沙盒失败需要修复隔离配置，不能把模型复述命令当作成功。

**答案慢**：将总时间拆成排队、检索、首 token 与生成阶段；缓存命中、冷启动和稳态分别测量。先定位阶段，再选择引擎机制或 MOD。

```text
日期、代码版本、模型修订：
硬件与资源分配：
协议与输入输出范围：
测试输入或可重建输入的种子：
成功率、延迟分位数、吞吐：
真实工具输出及完成事件：
失败样例与回滚结果：
结论及适用边界：
```
